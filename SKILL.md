# layero.json — конфигурация деплоя на Layero

`layero.json` — необязательный файл в корне репозитория. Задаёт фреймворк, команды сборки и установки, папку результата и версию Node. Файл сильнее настроек в панели Layero.

**Правило:** всё, что указано в файле, Layero обязан применить. Всё, что не указано, Layero определяет сам.

Файл пригодится, когда:
- деплой настраивает AI-агент — он кладёт нужные значения одним PR;
- конфигурация должна отличаться по веткам (staging ≠ production);
- в код-ревью видно, кто и зачем поменял сборку.

## Составление конфига

### Шаблон

```json title="layero.json"
{
  "$schema": "https://layero.ru/schema/layero-v2.json",
  "framework": "vite",
  "installCommand": "npm ci",
  "buildCommand": "npm run build",
  "outputDirectory": "dist",
  "nodeVersion": "22"
}
```

Все поля необязательны, включая `$schema`. Пустой файл `{}` допустим и означает «определяй всё сам».

Указывайте только то, что нужно поменять. Например, только папка результата:

```json title="layero.json — только папка результата"
{
  "$schema": "https://layero.ru/schema/layero-v2.json",
  "outputDirectory": "bundle"
}
```

### Поля

| Поле | Что задаёт | Умолчание / примечание |
|---|---|---|
| `framework` | Имя фреймворка, перебивает автоопределение | Допустимые значения — [список поддерживаемых фреймворков](https://github.com/LayeroInfra/layero-docs/blob/main/docs/getting-started/frameworks.md) |
| `installCommand` | Команда установки зависимостей | Воспроизводимая команда пакетного менеджера: `npm ci`, `yarn install --frozen-lockfile`, `pnpm install --frozen-lockfile` |
| `buildCommand` | Команда сборки | Например `pnpm build:prod` |
| `outputDirectory` | Папка со статикой относительно корня приложения; её содержимое Layero раздаёт по адресу проекта | Например `dist`, `build`, `out`, `dist/my-app/browser` |
| `nodeVersion` | Версия Node.js для сборки | Мажор `"22"`, точная `"22.14.0"` или `"lts"` |
| `startCommand` | Команда запуска для приложений, которые Layero запускает в контейнере, а не раздаёт файлами | Только для таких приложений |

### Короткие имена

Работают всегда, **не устаревшие**:

| основное | короткое |
|---|---|
| `installCommand` | `install` |
| `buildCommand` | `build` |
| `outputDirectory` | `output` |
| `nodeVersion` | `node` |
| `startCommand` | `start` |

Если в файле оба имени одного поля — применяется основное, о втором Layero скажет в логе сборки.

### `$schema`

```text
https://layero.ru/schema/layero-v2.json
```

Подключает автодополнение и подсветку ошибок в любом редакторе с поддержкой JSON Schema (VS Code, JetBrains, Neovim). На сборку не влияет.

Прежний адрес `https://layero.ru/schema/layero-v1.json` продолжает работать. Если в репозиториях стоит `v1`, менять не нужно — читается одинаково. В новых проектах указывайте `v2`.

### Приоритет значений

Для каждого поля отдельно:

```text
layero.json → настройки проекта → найденное в репозитории → умолчание фреймворка
```

Побеждает первое заданное. Пример: `package.json` со скриптом `"build": "vite build"` и `layero.json` с `"buildCommand": "npm run build:production"` — соберётся `npm run build:production`.

Порядок для `nodeVersion` длиннее, потому что версию объявляет и сам репозиторий:

```text
layero.json → настройки проекта → .nvmrc → .node-version → engines.node → умолчание Layero
```

Перекрытую версию из репозитория Layero называет в логе сборки, а не применяет молча.

Откуда взялось каждое значение, видно в логе:

```text
[config] framework=nextjs (from layero.json)
[config] node=22.18.0 (layero.json)
[config] node: layero.json перекрыл .nvmrc=20
[config] build=`npm run build` (from layero.json)
[config] output=out (default for nextjs)
```

### Расположение файла

- **Обычный проект** — в корне репозитория.
- **Монорепо** — в подпапке, указанной в настройках проекта как папка приложения. Указали `apps/web` — Layero читает `apps/web/layero.json`.

### Ошибки в файле

Layero никогда не отказывается собирать проект из-за `layero.json`. Всё, что не удалось прочитать, становится замечанием в логе сборки и в панели:

| Что в файле | Что делает Layero |
|---|---|
| Невалидный JSON | Сообщает и собирает так, как будто файла нет |
| Неизвестное имя поля | Сообщает, предлагает ближайшее известное, поле пропускает |
| Пустое значение | Сообщает, поле пропускает |
| `framework`, которого нет в репозитории | Предупреждает и всё равно применяет |

Замечания видны в мастере настройки и на странице деплоя, под содержимым файла.

### Поле из файла нельзя изменить в панели

Поле, объявленное в `layero.json`, панель показывает с бейджем имени файла вместо кнопки редактирования. Нажатие на бейдж открывает файл в репозитории. Меняйте значение в репозитории — там, где оно задано. Такое поле не участвует и в сохранении настроек проекта.

## Как составлять конфиг

1. Определите фреймворк, пакетный менеджер (по lockfile), скрипт сборки из `package.json` и версию Node (`.nvmrc` / `.node-version` / `engines.node`).
2. Укажите только поля, где нужно переопределить умолчания Layero. Если всё умолчальное устраивает — файл не нужен или пустой `{}`.
3. В новых проектах `$schema` — `v2`.
4. Проверьте, что `outputDirectory` совпадает с реальной папкой результата сборки.
5. Для монорепо положите файл в папку приложения, а не в корень.
